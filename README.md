# fleet-rdp

One-click RDP launcher for Windows. A launcher is a small `.exe` that carries
one connection (host, port, login, password). A double-click saves the login in
Windows Credential Manager and opens `mstsc` full screen, with no prompts.

The `.exe` is as secret as the password it carries. Treat it that way.

## Build

    pwsh ./build.ps1 [-Version v0.1.2]

`-Version` (default `v0.0.0`) goes into the file properties of all three
executables; the launcher also gets a default icon of four 32-bit DIBs that
the FleetView dashboard patches per server. The icons and the `.syso` resource
files are generated by the build and are not committed.

Produces `dist/fleet-rdp-launcher.exe` (the template; do not run it),
`dist/fleet-rdp.exe` (the CLI) and `dist/fleet-rdp-maker.exe` (the maker, a
GUI that embeds the launcher from the same build), and prints their SHA-256.
All are windows/amd64. On another OS, `go build ./cmd/fleet-rdp` builds the CLI.

## Releasing

    pwsh ./release.ps1 -Version v0.1.2 -Notes 'what changed' [-ProbeHost H -ProbePort P]

Requires a clean tree with everything pushed to `origin/main`. It builds,
hashes, optionally probes a live server's certificate, tags and pushes,
creates the GitHub release with three assets, then downloads the published
launcher and maker and compares their SHA-256. It ends by printing the FleetView pin
command (`node scripts/pin-launcher.mjs <version>`) and the template hash.
`-DryRun` does the checks, build and probe and prints the rest without
tagging. `-SkipPushCheck` is for testing the script only.

## Make a launcher

    fleet-rdp build --host 10.0.0.5 --port 2157 --user vlad --name SGCLOUD -o SGCLOUD.exe

- The password is asked for at a hidden prompt; nothing is echoed and nothing
  lands in the shell history. This is the way to give it. It is never taken
  from an argument.
- `FLEET_RDP_PASSWORD` is for scripts that pull the password from a secret
  store and set it for one process:

      cmd:         set FLEET_RDP_PASSWORD=...
      PowerShell:  $env:FLEET_RDP_PASSWORD = "..."

  Do not type the password into an interactive shell line: it goes into the
  history (PSReadLine saves it to `ConsoleHost_history.txt`).
- The built `.exe` carries the password. Keep it in a folder only its owner can
  read, and send it only to the person it is for.
- `--template` defaults to `fleet-rdp-launcher.exe` beside the CLI. A template
  that already carries a payload is refused.
- `--cert-sha256 <64 hex>` pins the server certificate. Without it the first
  run trusts the certificate the server shows (trust on first use).
- `--monitors auto|one|all` chooses the screens `mstsc` uses. `auto` (the
  default) uses all of them when Windows reports more than one monitor.
- `fleet-rdp inspect SGCLOUD.exe` prints the payload with the password as `***`.
- After the server's RDP certificate renews, `mstsc` shows its certificate
  dialog once (the stored pin is kept; "zero clicks" holds until the renewal).

- `fleet-rdp probe HOST PORT` connects the way an RDP client does and prints
  `<sha256 of the server certificate>  <elapsed>`. Use it to see what
  certificate a server shows, or to get the value for `--cert-sha256`.

The payload's `monitors` mode (`auto`, `one` or `all`, set by the dashboard or
by `fleet-rdp build --monitors`) decides first: `auto` uses `/multimon` when
Windows reports more than one monitor. The launcher accepts `--single` and
`--multi` to override that mode; if both are given, the last flag wins.

## Maker (for people outside Fleet)

`fleet-rdp-maker.exe` is one file, from the GitHub release. Run it and fill in
Server (`host`, `host:port` or `[v6]:port`), Login and Password.

**More options** holds:

- Name: shown in the launcher's dialogs and used as the file name.
- Monitors.
- Certificate SHA-256, with Check. Check needs WARP where the server is behind
  Zero Trust. Empty means trust on first use.
- People: one ZIP with a launcher each.

Create launcher... saves a ZIP (or one `.exe` for one person). Send the ZIP the
way you would send the password itself: it contains it.

The icon comes from the same invader generator as the FleetView dashboard. The
maker keys it on the Host it is given, in the hash colour on the no-organization
tile, so a Fleet server reached by IP looks different from its dashboard
download.
